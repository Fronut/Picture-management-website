## 1. 系统概览

- **项目名称**：Picture Management Website
- **整体架构**：单体仓库，包含三套可独立运行的服务：
  - 后端：Spring Boot 3（Java 17），负责认证、业务逻辑和数据持久化。
  - 前端：Vue 3 + Vite + TypeScript，提供图片管理的 Web 界面。
  - AI 微服务：Flask 应用，为系统提供图片标签生成和对话式检索能力。
- **主要功能**：
  - 用户注册 / 登录 / 退出登录。
  - 图片批量上传、存储与删除。
  - EXIF 信息展示（拍摄时间、设备、参数等）。
  - 图片缩略图生成与多尺寸访问。
  - 标签管理：自定义标签、AI 自动标签、热门标签统计。
  - 图片搜索：条件过滤 + AI 自然语言搜索。
  - 图片编辑：裁剪、旋转、色调调整等基础编辑。
  - AI 对话：使用自然语言描述需要的图片，由 AI 帮你找到合适的结果。

### 1.1 作业要求与实现情况对照

下表按老师布置的“基本功能 / 增强功能”顺序，简要说明本项目的实现情况，方便对照评分细则：

1. **用户注册、登录（基本功能 1）**

   - 注册表单要求用户名、邮箱、密码必填：用户名和密码长度均不少于 6 个字符，邮箱做格式校验，用户名和邮箱在数据库中具有唯一约束。
   - 登录后才能访问图片相关的业务页面，未登录访问受保护路由会被自动跳转到登录页。

2. **上传图片（基本功能 2）**

   - 通过浏览器选择或拖拽方式上传本地图片，前端适配 PC 和手机浏览器；
   - 后端对文件类型和大小进行校验，通过接口将图片保存到服务器文件系统中。

3. **基于 EXIF 的辅助信息与分类（基本功能 3）**

   - 后端在图片上传完成后自动解析 EXIF 信息（如拍摄时间、相机型号、分辨率等），写入专门的数据表；
   - 在图片详情页展示这些信息，并在搜索时可作为过滤条件使用。

4. **自定义标签（基本功能 4）**

   - 在图片详情页或标签管理页，可以为图片添加、删除自定义标签，用于后续检索；
   - 标签与图片之间为多对多关系，保存在 tags 和 image_tags 表中。

5. **缩略图生成（基本功能 5）**

   - 后端在原图上传后，自动生成多种尺寸的缩略图文件，并记录在 thumbnails 表中；
   - 前端列表和轮播组件优先使用缩略图，以提升加载速度和显示效果。

6. **图片信息入库（基本功能 6）**

   - 图片的路径、尺寸、拥有者、描述、隐私设置、哈希值等元数据均保存在 MySQL 数据库中；
   - 仓库中提供建表脚本和迁移文件，方便老师在本地重建数据库结构。

7. **多条件查询（基本功能 7）**

   - 前端提供单独的“图片搜索”页面，支持按关键词、标签、时间范围、分辨率、拍摄设备、隐私设置等多条件组合查询；
   - 查询结果分页显示，可以按时间或其他字段排序。

8. **友好展示与轮播（基本功能 8）**

   - 仪表盘页面展示“高光图片”区域，支持轮播展示若干精选图片；
   - 图片列表采用卡片形式显示缩略图及关键信息，兼顾 PC 和手机端的排版效果。

9. **简单编辑（基本功能 9）**

   - 提供图片编辑对话框，支持对选定图片进行裁剪、旋转和基础色调调整；
   - 编辑结果由后端生成新图像文件并更新数据库记录，前端实时刷新预览。

10. **删除功能（基本功能 10）**

- 在列表和详情页均提供删除按钮，删除前有二次确认提示；
- 删除操作会更新数据库中的图片记录，并同步影响前端展示。

11. **移动端友好显示（基本功能 11）**

- 前端采用响应式布局和常见 UI 组件，在手机浏览器和微信内置浏览器中能够正常访问和操作；
- 核心操作（登录、上传、浏览、搜索、编辑、删除）均可在手机端完成。

12. **AI 标签（增强功能 1）**

- 通过独立的 AI 微服务，对图片进行内容分析并返回多类型标签（如场景、人物、动物等），用户可以选择性应用到图片上；
- 这些 AI 标签同样存入标签系统，可与自定义标签一起参与检索。

13. **MCP 接口与对话式检索（增强功能 2）**

- 在工具目录中提供了基于 MCP 协议的图片检索服务，实现通过大模型对话的方式，让模型调用搜索接口检索站内图片；
- AI 对话页面也利用这一能力，将自然语言转换为图片搜索条件并展示结果。

## 2. 环境与运行方式

本项目支持两种常见运行方式：

1. **本地开发模式（后端 / 前端 / AI 服务分别启动）**。
2. **Docker Compose 一键容器化运行**。

### 2.1 环境前置条件

在开始前，请确认：

- 已安装下列软件（任意方式安装均可）：
  - Docker 与 Docker Compose（用于容器化运行，以及启动 MySQL / Redis）。
  - JDK 17（用于本地运行 backend）。
  - Node.js 与 npm（推荐 Node 18+，用于本地运行 frontend）。
  - Python 3.10+（用于本地运行 ai-service）。
- Windows 用户推荐在 **PowerShell** 或 **WSL** 中运行命令。

> 提示：课程环境中，如果仅做功能演示，推荐直接使用 `docker-compose up --build` 一次性拉起所有服务。

### 2.2 Docker Compose 一键运行

1. 在仓库根目录打开终端（PowerShell / bash 均可）。
2. 执行：

   ```bash
   docker-compose up --build
   ```

3. 等待镜像构建与容器启动完成，正常情况下会启动以下容器：

   - `backend`：Spring Boot 后端服务，默认对外暴露 `http://localhost:8080`（由 nginx/compose 统一转发）。
   - `frontend`：Vue 前端服务，通常经由 Nginx 反代，以 `http://localhost:80` 或 `http://localhost:5173` 形式访问（视 compose 配置而定）。
   - `ai-service`：AI 微服务，内部以 `http://ai-service:5000` 形式提供服务。
   - `mysql`：MySQL 数据库，数据卷持久化。
   - `redis`：Redis 缓存实例。
   - `nginx`：反向代理、静态文件服务。

4. 打开浏览器访问：

   - 若使用 Nginx 统一入口：访问 `http://localhost/`。
   - 若前端单独运行：访问 `http://localhost:5173/`（Vite 默认端口）。

5. 第一次访问若尚未创建账户，可按“3. 用户注册与登录”章节进行操作。

### 2.3 本地开发分服务运行

若你希望分别调试后端 / 前端 / AI 服务，可以按以下步骤：

#### 2.3.1 启动数据库与缓存

在项目根目录执行：

```bash
docker-compose up -d mysql redis
```

- 此命令仅启动 MySQL 与 Redis，方便后端本地连接。
- 数据会保存在本地 Docker 卷中，停止容器不会丢失。

#### 2.3.2 启动后端（Spring Boot）

1. 打开终端，进入 backend 目录：

   ```bash
   cd backend
   ```

2. 运行 Spring Boot：

   ```bash
   ./mvnw spring-boot:run
   ```

3. 默认情况下，后端服务会在 `http://localhost:8080` 启动，并：
   - 使用 application.yml 中的 `dev` profile。
   - 连接前面启动的 MySQL 与 Redis。
   - 通过环境变量 `AI_SERVICE_URL` 访问 AI 微服务。

#### 2.3.3 启动前端（Vue 3 + Vite）

1. 打开新终端，进入 frontend 目录：

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

2. Vite 默认在 `http://localhost:5173` 启动开发服务器。

3. 若需要自定义后端 API 地址，可在 frontend 根目录配置 `.env.local`：

   ```bash
   VITE_API_BASE_URL=http://localhost:8080
   ```

#### 2.3.4 启动 AI 微服务（Flask）

1. 打开终端，进入 ai-service 目录：

   ```bash
   cd ai-service
   pip install -r requirements.txt
   ```

2. 通过内置 main 启动：

   ```bash
   python -m app.main
   ```

3. 默认监听 `http://localhost:5000`，后端通过 `AI_SERVICE_URL` 环境变量来访问：

   ```bash
   # 在 backend 进程环境中配置，例如 PowerShell
   $env:AI_SERVICE_URL="http://localhost:5000"
   ```

## 3. 用户注册与登录

本系统使用 **JWT + 刷新令牌** 的方式进行认证。前端已封装好所有交互，你只需要按界面提示操作即可。

### 3.1 首次注册账号

1. 在浏览器中打开前端页面（例如 `http://localhost:5173`）。
2. 点击页面中的“注册”或直接访问 `/auth/register` 路由。
3. 按表单提示填写：
   - 用户名（必填，唯一）。
   - 邮箱（必填，格式需合法）。
   - 密码（必填，建议 8 位以上，包含大小写与数字）。
4. 提交后，若注册成功，系统会自动返回 JWT 令牌并建立登录状态，前端会跳转到仪表盘 `/dashboard`。

> 技术说明：前端调用 `POST /api/auth/register`，请求体为 RegisterRequest；后端返回 `ApiResponse<AuthResponse>`，其中包含 `accessToken` 与 `refreshToken`。

### 3.2 登录已有账号

1. 若已拥有账号，可以直接访问 `/auth/login`。
2. 在登录界面输入：
   - 用户名或邮箱（视后端实现而定）。
   - 密码。
3. 登录成功后：
   - 前端会将 `accessToken` 保存在浏览器本地（`pm_auth_token` 键）。
   - 后续所有 API 请求都会自动携带 `Authorization: Bearer <token>` 头部。
   - 页面自动跳转到 `/dashboard`。

> 若你已登录，再次访问 `/auth/login` 或 `/auth/register`，路由守卫会自动跳转回 `/dashboard`，避免重复登录。

### 3.3 退出登录

1. 在任意已登录页面（如仪表盘右上角菜单）点击“退出登录”。
2. 前端会调用登出接口并清理本地 token。
3. 页面会跳转回登录页。

> 技术说明：后端提供 `POST /api/auth/logout`，请求体为 `RefreshTokenRequest`，用于在服务端注销刷新令牌。前端在本地也会同步清理会话。

### 3.4 会话过期与自动跳转

- 当 accessToken 过期或无效时，后端会返回 `401 Unauthorized`。
- 前端 `apiClient` 拦截器会在收到 401 时：
  - 调用 `authStore.logout({ silent: true, notifyServer: false })` 清理本地会话。
  - 自动跳转到 `login` 路由，并附带 `redirect` 参数，以便重新登录后跳回原页面。

## 4. 仪表盘与高光展示

### 4.1 仪表盘入口

- 登录后默认跳转到 `/dashboard`，对应页面为 DashboardHome。
- 仪表盘主要展示：
  - 最近上传/高光图片的缩略图。
  - 全局快捷入口（上传图片、搜索图片、AI 对话检索等）。

### 4.2 高光轮播

- 系统会从后端接口（如 `GET /api/images/highlights`）拉取一组“高光图片”。
- 前端页面提供：
  - 自动轮播模式：定时切换当前展示图片。
  - 手动切换：用户可使用左右箭头或缩略图快速切换。
  - 全屏预览：可全屏查看当前高光图片。

> 高光规则通常基于图片是否公开、是否被标记为高光等。若你上传的图片尚未显示在高光列表中，可能是尚未满足后端的筛选条件。

## 5. 图片上传

图片上传是本系统的核心功能之一，支持**批量上传**与**上传前预览**。

### 5.1 打开上传页面

1. 登录后，在导航栏中选择“上传图片”，或直接访问 `/images/upload` 路由。
2. 打开页面后，你会看到一个上传表单与文件列表区域。

### 5.2 选择文件

页面通常提供两种添加图片的方式：

1. 点击“选择文件”按钮，从本地文件系统中选择一张或多张图片。
2. 将图片从文件夹拖拽到页面指定区域完成添加。

> 限制：
>
> - 默认最大单张图片大小为 20MB（配置可调整）。
> - 仅允许常见图片格式（如 JPEG / PNG 等），非法格式会被前端或后端拒绝。

### 5.3 设置图片属性

在文件列表中，每个待上传条目通常提供以下可选字段：

- 图片描述（可选）：用于后续搜索与展示。
- 隐私设置：如“仅自己可见 / 公开”。
- 标签初始值：可在上传时预先填写一些标签（如果界面提供）。

若界面提供**批量设置**功能，你可以：

- 为所有选中的图片统一设置描述或隐私级别。
- 或对单张图片做单独的说明。

### 5.4 执行上传

1. 确认列表中需要上传的图片及属性设置无误后，点击“开始上传”按钮。
2. 上传过程中，界面会展示：

   - 当前进度（已完成 / 总数）。
   - 每张图片的上传状态（排队中 / 上传中 / 成功 / 失败）。
   - 若上传失败，错误信息会在该条目下方显示。

3. 上传成功的图片，可通过以下方式进一步处理：
   - 点击“查看详情”跳转到图片详情页。
   - 点击“管理标签”直接打开标签管理抽屉（如果前端提供入口）。

> 技术提示：后端的 `ImageServiceImpl` 会对上传的文件进行：
>
> - 类型与大小校验。
> - 计算内容哈希 `content_hash`，避免重复上传完全相同的图片。
> - 将原图保存到 `/app/uploads/<user>/<imageId>/`。
> - 异步生成缩略图并写入缩略图表和磁盘文件。

## 6. 图片浏览与详情

### 6.1 图片列表与搜索入口

- 访问 `/images/search` 页面可以看到图片列表与搜索条件面板。
- 默认情况下，会展示当前用户可见的图片集合，通常包含：
  - 自己上传的所有图片。
  - 其他用户上传但设置为公开的图片（视后端权限策略而定）。

### 6.2 打开图片详情

在列表中点击某张图片的卡片或“详情”按钮，可跳转到 `/images/:imageId` 页面。

在详情页，你可以看到：

- 图片原图或大尺寸预览。
- 基本信息：
  - 标题 / 描述。
  - 文件名、大小、分辨率。
  - 上传时间、所有者等。
- EXIF 信息：
  - 拍摄日期、相机型号。
  - 光圈、曝光时间、ISO、焦距等。
- 标签区域：
  - 自定义标签列表。
  - AI 标签列表。
  - 标签类型与置信度等信息。

### 6.3 下载图片

在详情页中通常提供：

- 下载原图按钮：调用后端原图下载接口，例如 `GET /api/images/{id}/content`。
- 下载缩略图按钮：调用后端缩略图接口，例如 `GET /api/images/{id}/thumbnail/{thumbId}` 或按尺寸访问。

> 提示：
>
> - 若你没有该图片的访问权限（例如是他人设置为“仅自己可见”的图片），下载会失败或直接在列表中不可见。

### 6.4 删除图片

- 在列表或详情页，通常会提供“删除”操作按钮。
- 点击删除后：
  - 系统会弹出二次确认对话框。
  - 确认后调用后端 `DELETE /api/images/{id}`。

> 具体是软删除还是物理删除，取决于后端实现。一般建议在使用时确认是否支持恢复。

## 7. 图片搜索

本系统支持**多条件组合搜索**与**AI 自然语言搜索**。

### 7.1 条件过滤搜索

在 `/images/search` 页面左侧（或顶部）通常有搜索表单，常见字段包括：

- 关键词：
  - 匹配图片描述、标题、标签等。
- 标签：
  - 选择一个或多个标签，只显示包含这些标签的图片。
- 时间范围：
  - 上传时间区间；可能也支持拍摄时间区间。
- 分辨率 / 尺寸：
  - 按最小/最大宽高过滤。
- 设备 / 相机：
  - 根据 EXIF 中的机型字段过滤。
- 隐私过滤：
  - 是否只显示“公开图片”，或“仅自己上传的图片”。

你可以自由组合上述条件，然后点击“搜索”按钮，即可从后端获取匹配结果。

搜索结果列表支持：

- 分页：下一页/上一页按钮或页码跳转。
- 排序：按上传时间、分辨率、文件大小等排序。

### 7.2 使用 AI 辅助搜索

在搜索页中，通常会集成 AI 搜索入口，例如：

- 一个输入框，允许你直接输入自然语言，如：
  - “帮我找一下去年暑假在海边拍的夕阳照片。”
  - “包含蓝天和大海、画面中有人物的照片。”

前端会：

1. 将你的自然语言请求发送到后端 AI 对话接口（进而转发到 AI 微服务）。
2. AI 服务调用外部大模型，对自然语言进行解析并生成更结构化的查询条件，例如：
   - 时间范围；
   - 是否仅查看自己的图片；
   - 场景 / 主题 / 氛围相关标签等。
3. AI 服务再调用后端的 `/api/images/search` 与 `/api/tags/available` 等接口，得到一组结果。
4. 前端展示：
   - AI 生成的搜索说明（例如“为你筛选了 2024 年 7–8 月间，地点为海边、画面中有人物的照片 ...”）；
   - 匹配结果的图片列表。

> 在部分实现中，你还可以一键将 AI 推理出的搜索条件“同步到普通搜索表单”，方便你进一步微调再搜索。

## 8. 标签管理

标签是帮助你组织和快速检索图片的重要工具，本系统支持：

- 自定义标签。
- AI 生成标签。
- 热门标签统计。

### 8.1 打开标签管理

你可以通过多种方式打开标签管理界面：

1. 从图片详情页点击“管理标签”按钮，打开侧边抽屉组件。
2. 访问专门的标签管理页 `/images/:imageId/tags`，可一次性查看该图片所有标签。

### 8.2 添加自定义标签

1. 在标签管理区域找到“添加标签”输入框。
2. 输入一个或多个标签名称，例如：“旅行”“家人”“落日”。
3. 点击“添加”或回车确认，系统会：
   - 调用后端 `POST /api/tags/custom` 等接口。
   - 在 `tags` 和 `image_tags` 表中添加对应记录。

> 自定义标签通常类型为 `CUSTOM`，便于与自动或 AI 标签区分。

### 8.3 生成 AI 标签

1. 在标签管理界面中找到“AI 生成标签”按钮。
2. 点击后，前端会请求后端调用 AI 微服务的 `POST /ai/v1/tags/suggest` 接口。
3. AI 服务会：
   - 下载对应图片（或使用已有 URL / base64 数据）。
   - 调用视觉模型（如 CLIP 或 Baidu API）生成标签建议。
4. 生成完成后，前端界面会：
   - 展示建议标签列表及各自的置信度。
   - 允许你“全部应用”或“勾选部分标签再应用”。

> 一般来说，对应的后端接口会将应用后的标签写入数据库，并标记类型为 `AI` 或 `AUTO`，以便在界面和统计中区分。

### 8.4 删除标签

- 在标签列表中，每个标签右侧通常有删除图标或按钮。
- 点击后，系统会：
  - 调用后端删除接口（如 `DELETE /api/tags/{tagId}` 或按图片-标签关系删除）。
  - 成功后前端更新界面，将该标签移除。

### 8.5 查看热门标签

- 系统提供热门标签接口（例如 `GET /api/tags/popular`）。
- 在前端标签管理或搜索面板中，会展示一组“热门标签云”，显示当前使用次数较高的标签。
- 点击热门标签，可直接：
  - 在当前图片上添加该标签。
  - 或将其添加到搜索条件中，快速找到相关图片。

## 9. 图片编辑

图片编辑功能主要针对基础编辑需求，如裁剪、旋转与色调调整。

### 9.1 打开编辑对话框

1. 在图片详情页中点击“编辑图片”按钮。
2. 会弹出一个编辑对话框（如 `ImageEditDialog` 组件）：
   - 左侧或上方显示当前图片预览。
   - 右侧提供编辑控制面板。

### 9.2 可用编辑操作

常见的编辑操作包括：

- **裁剪**：
  - 手动拖拽裁剪框，或选择常见比例（例如 1:1 / 16:9）。
- **旋转**：
  - 顺时针或逆时针旋转 90°。
  - 某些实现可能支持任意角度微调。
- **色调调整**：
  - 亮度、对比度、饱和度、冷暖色等滑块调整。

所有调整都会有**实时预览**，方便你在应用前先查看效果。

### 9.3 应用编辑

1. 在编辑完成后点击“应用”或“保存”。
2. 前端会将编辑参数提交到后端 `POST /api/images/{id}/edit` 接口。
3. 后端会：
   - 根据原图与编辑参数生成新图片。
   - 替换或新建图片文件。
   - 更新数据库中的尺寸、缩略图等相关字段。
4. 前端收到成功响应后：
   - 自动刷新当前详情页的图片预览与 EXIF / 尺寸信息。

> 注意：编辑会不可逆地改变图像，如需保留原图，建议在上传前自行备份或配置“生成副本”模式（视项目实现）。

## 10. AI 对话检索

与常规条件搜索不同，AI 对话检索允许你直接用自然语言描述需求，由 AI 帮你转化为搜索条件并返回结果。

### 10.1 进入 AI 对话页面

1. 从导航栏选择“AI 搜索”或“对话检索”。
2. 实际路由为 `/ai/chat`，页面组件通常为 `AiChat.vue`。

### 10.2 基本使用流程

1. 在对话输入框中输入你的需求，例如：
   - “找出所有在黄昏拍摄、有海、有人的照片。”
   - “帮我找到 2024 年 1 月到 3 月在校园拍的樱花照片。”
2. 点击发送或回车。
3. 页面会显示：
   - 你的提问。
   - AI 的回答，其中包括：
     - 对你需求的总结。
     - 解析出的搜索条件（时间、地点、标签、是否只看自己的图片等）。
   - 触发的工具调用轨迹（可选显示）：比如调用 `/api/images/search` 的参数。
4. 同时，页面下方会展示 AI 按这些条件查询到的图片列表，类似普通搜索结果展示。

### 10.3 授权与安全

- AI 微服务在调用后端接口进行搜索时，需要一个合法的 JWT 令牌。
- 前端通常会将当前用户的 token 以安全的方式传递给 AI 服务（例如放入请求体 `authToken` 字段），再由 AI 服务转发给后端。
- 若 AI 服务未配置或不可用：
  - 调用 `POST /ai/v1/search/chat` 时会返回 503 错误，前端会给出“AI 功能未启用”提示。

## 11. 常见问题与排错

以下列出使用过程中可能遇到的一些问题及排查方向。

### 11.1 无法访问前端页面

**现象**：浏览器访问 `http://localhost` 或 `http://localhost:5173` 时无法打开页面。

**排查步骤**：

1. 检查前端是否启动：
   - 使用 Docker：在终端中运行 `docker ps`，确认前端容器是否在运行。
   - 本地运行：检查执行 `npm run dev` 的终端是否有报错。
2. 端口是否冲突：
   - 若 5173 被占用，Vite 会提示新的端口号，请查看终端输出并使用新的地址访问。
3. 代理 / 防火墙：
   - 检查是否有本地代理软件拦截了 localhost 访问。

### 11.2 登录后接口全部返回 401

**现象**：

- 登录成功后，部分或所有后端请求均提示“未授权”或自动跳回登录页面。

**可能原因与解决**：

1. 浏览器禁止了本地存储：
   - 系统使用 `localStorage` 保存 `pm_auth_token`，若浏览器隐私设置过高可能被阻止。
2. 服务器时间误差过大：
   - JWT 校验与过期时间依赖服务端时间。
   - 若服务器时间严重错误，可能会导致 token 立即过期。
3. 后端 JWT 密钥变更：
   - 开发中修改了 `JWT_SECRET` 后，需要重新登录以获取新签发的 token。

### 11.3 图片上传失败

**现象**：上传时状态显示“失败”或前端提示错误。

**排查要点**：

1. 图片体积过大：
   - 默认为 20MB 上限；可在后端配置中调整。
2. 图片格式不支持：
   - 请确认文件为常见图片格式（jpg/png 等）。
3. 磁盘路径不可写：
   - 后端在容器或本地必须有 `/app/uploads` 路径的写权限。
4. 数据库连接失败：
   - 若后端无法连接 MySQL，上传时在服务端会报错。

### 11.4 AI 标签 / AI 对话不可用

**现象**：

- 生成 AI 标签时返回错误。
- AI 对话页面提示“AI 功能未启用”或 503。

**排查要点**：

1. AI 微服务是否启动：
   - 使用 Docker：在终端运行 `docker ps`，确认 `ai-service` 容器在运行。
   - 本地运行：查看 `python -m app.main` 终端是否输出错误。
2. 环境变量配置：
   - 后端 `AI_SERVICE_URL` 是否指向正确地址（如 `http://ai-service:5000` 或 `http://localhost:5000`）。
   - 若启用了外部图像识别服务或大模型服务，相应的 Key 是否已在 ai-service 环境变量中配置。
3. 网络连通性：
   - 在后端容器中 `curl http://ai-service:5000/ai/v1/health` 看能否访问。

### 11.5 图片详情中 EXIF 为空

**现象**：

- 某些图片详情页中 EXIF 信息为空或只显示部分字段。

**说明**：

- 并非所有图片都包含完整 EXIF 信息，特别是：
  - 截图或通过某些社交平台下载的图片。
  - 部分编辑软件导出的图片会清除 EXIF 信息。
- 确认图片原始来源是否包含 EXIF，如无则属正常现象。

## 12. 小结与教师验收建议

老师或助教在验收时，可以按下面的顺序快速走一遍核心功能：

1. **启动环境**
   - 推荐使用 `docker-compose up --build` 一次性启动所有服务；
   - 或按照第 2 章说明分别启动数据库、后端、前端和 AI 服务。
2. **注册与登录**
   - 访问前端地址，注册一个新账号并登录；
   - 观察登录失败、重复用户名等边界情况的提示信息是否合理。
3. **上传与浏览图片**
   - 通过“上传图片”页面一次性上传多张不同尺寸、格式的图片；
   - 在“图片搜索/列表”页面查看刚上传的图片是否展示完整缩略图和基本信息。
4. **详情页与 EXIF / 标签**
   - 随机点开一张图片，查看 EXIF 信息是否正确解析（若原图包含 EXIF）；
   - 尝试添加几条自定义标签并删除其中一条，检查界面与后端状态是否同步。
5. **搜索与 AI 功能**
   - 在搜索页测试按关键词、标签和时间范围等组合条件过滤；
   - 在 AI 对话页面输入 1 ～ 2 条自然语言需求，观察 AI 给出的搜索说明及对应的结果列表。
6. **编辑与删除**
   - 对一张图片进行裁剪或旋转操作，确认编辑前后显示的尺寸发生合理变化；
   - 尝试删除一张图片，检查列表和详情页是否即时更新。

通过以上流程，大致可以覆盖本次课程设计中实现的主要功能点。
